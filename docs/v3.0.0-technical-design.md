# ModuleCrafter 3.0.0 开发技术设计

> 状态：**实现中，实机待验收**  
> 基线：ModuleCrafter 3.0.0，Probably Stolen 0.46D，Unity 2021.3.45f2，Mono，`netstandard2.1`  
> 关联文档：`docs/v3.0.0-update.md`、`docs/v3.0.0-test-cases.md`  
> 本文描述 3.0.0 的实现结构。规则测试、构建和官方扫描已完成，但不代表全部实机行为已经验收。

## 1. 技术目标与约束

### 1.1 目标

- 以追加模块方式实现专精、19 种双配方、通用组件、28 种强化、专用效果、售价和王尔德升级。
- 保留现有 9 种配方、槽位、夜间流程、B/N 强化快照、视觉与音效、商店怜悯和旧存档。
- 规则层无 Unity 依赖，游戏适配层只负责物品、机器、UI 和原生事件。
- 所有游戏状态读取与修改均在主线程执行。

### 1.2 已核实的现状

- `ModuleCrafterMod` 使用 `IMod`，在 `OnEnable` 注册目录、游戏加载、tooltip、商店与 Harmony，在 `OnDisable` 对称注销。
- `ModuleCrafterMachine` 使用槽位 0～5，槽位 6 仅用于 2.0.x 遗留强化物品迁移；材料栏与隐藏暂存栏均为 8×6。
- `ModuleCrafterEnhanceState` 已保存 B（未强化三围）与 N（等级），现有售价由 `CatalogValue` 重算。
- `ModHelper.SetModData*` 读写 `PlayerStore.Instance.ModData()`，可用于按当前存档保存迁移版本。
- 游戏已提供 `StartingScenario.Register`、`NetworkUpgrade.RegisterModUpgrade`、`NetworkUpgrade.RegisterTabLabel` 及对应移除入口。

### 1.3 禁止事项

- 不修改游戏程序集，不补丁 ModLoader、扫描器或信任机制。
- 不复制游戏程序集、反编译代码或第三方程序集到发布包。
- 不重写整个制造机、强化器或原生机器来添加少量行为；使用官方事件和窄适配点。
- 不从玩家全局库存读取制造或强化材料。
- 不在 UI 预览中扣费、掷骰、迁移存档或推进任务。

## 2. 总体架构

```text
官方 IMod / ModHook / Harmony
        │
        ▼
生命周期与注册层
Scenario / Items / NetworkUpgrades / Stock / UI / Migration
        │
        ▼
游戏适配层
Machine / MaterialPlanner / EnhanceState / SpecialEffectAdapters / PriceState
        │
        ▼
纯规则层
RecipeCatalog / WorkloadRules / EnhanceRules / SpecialEffectRules / MigrationRules
        │
        ▼
纯规则测试与可重复数据
```

依赖方向只允许：**生命周期 → 游戏适配 → 纯规则**。纯规则不得引用 `GameItem`、`PlayerStore`、UnityEngine 或 UI 类型。

### 2.1 计划新增模块

| 模块 | 职责 |
| --- | --- |
| `ModuleCrafterScenario` | 注册专精、发放开局物品、判断当前存档是否为制造商 |
| `ModuleCrafterRecipeCatalog` | 芯片、产物、档位、材料、违禁等级和配方版本的唯一数据源 |
| `ModuleCrafterComponentItem` | 通用组件创建、堆叠、价值和所有权规则 |
| `ModuleCrafterMaterialPlanner` | 按实体与 `unitCount` 规划、锁定、暂存、消耗和返还材料 |
| `ModuleCrafterWorkloadRules` | 工作量、动态晚数及旧 `BaseNights` 兼容计算 |
| `ModuleCrafterSpecialEffectRules` | 19 种效果在 +0／+10／+12 的纯数据映射 |
| `ModuleCrafterSpecialEffectAdapters` | 将效果接入水培、DNA、打印、警报、熔炉、蒸发器和化学设备 |
| `ModuleCrafterNetworkUpgrades` | 王尔德页签、前置、购买回调、订货和工艺状态 |
| `ModuleCrafterMigration` | 按存档执行一次性迁移、失败回滚和旧任务兼容 |

现有 `ModuleCrafterMachine`、`ModuleCrafterEnhanceState`、`ModuleCrafterStock`、`ModuleCrafterLocalization` 只做必要扩展，不另建平行制造系统。

## 3. 生命周期与注册顺序

### 3.1 `OnEnable`

按以下顺序执行：

1. 设置活动标记，初始化日志和纯数据目录。
2. 注册专精及图标／文本。
3. 注册物品目录：现有物品、19 种芯片、通用组件。
4. 注册王尔德页签和升级定义；注册本身不发放奖励。
5. 注册制造、强化、tooltip、商店、客人和游戏加载事件。
6. 应用 Harmony 窄补丁。
7. 在游戏已加载时执行一次迁移，之后恢复强化状态和视觉。

不得假设 `PlayerStore`、存档、场景或机器在 `OnEnable` 时已存在；这些操作延迟到 `OnGameLoadedLate`。

### 3.2 `OnDisable`

1. 活动标记置为 false，阻止新的制造、强化、订货和迁移。
2. 注销专精、王尔德、目录、UI 和全部 ModHook。
3. 停止视觉刷新，按 B、N、V0 恢复未强化三围、基础效果和基础售价。
4. `UnpatchAll(HarmonyId)`，恢复原生机器行为。
5. 停止协程、清理临时 UI 和回调，不删除存档标签或玩家物品。

禁用后不删除 `MODULE_CRAFTER_SAVE_VERSION`、B、N、V0 或原生扫描／派系状态，重新启用时可继续恢复。

## 4. 数据目录与稳定 ID

### 4.1 配方版本

```csharp
public enum ModuleCrafterRecipeVariant
{
    Legacy = 0,
    Themed = 1,
    Universal = 2
}
```

- 旧任务缺少版本标记时读取为 `Legacy`。
- 新任务只能保存 `Themed` 或 `Universal`。
- 新芯片枚举只在现有成员末尾追加，禁止重排现有 `ModuleCrafterChipKind`。
- 新档位同样在现有 `ModuleCrafterTier` 末尾追加 `Specialized`、`Precision`、`Prototype`。

### 4.2 配方记录

计划将配方扩展为以下纯数据记录：

```text
RecipeDefinition
- chipKind / chipItemId / outputItemId
- tier / workload / baseSuccessPercent / softCapPercent / failureCorruptPercent
- themedRequirements / universalRequirements
- contrabandLevel（0 表示合法）
- fixedNativeShape（新专用模组为 true）
- allowRandomUniversalShape / allowRandomUniversalEffects（新专用模组均为 false）
```

19 组材料以 `docs/v3.0.0-update.md` 第 8 节为唯一数值源，代码和测试均从同一目录生成，避免两份手写配方漂移。

### 4.3 新物品 ID

- 通用组件：`module_crafter_universal_component`。
- 19 种芯片沿用 `module_crafter_chip_<stable_name>`，不得以数组索引作为存档身份。
- 产物直接使用原版物品 ID，确保原生机器识别其模组类型和标签。

## 5. 专精技术方案

### 5.1 注册

创建 `StartingScenario`：

- `id = module_crafter_manufacturer`
- `startType = MODDED`
- `source = module_crafter`
- `tag = 进阶开局`
- `skipIntro = true`
- `comingSoon = false`、`hidden = false`
- `onStart` 只负责开局物品与初始状态，不修改其他专精装备。

原生专精 UI 负责图标、分页、标题、描述、初始拥有和继续按钮，不新增平行选择界面。

### 5.2 开局发放

`onStart` 在主线程执行：

1. 创建玩家所有、非赃物的制造机和性能芯片。
2. 依次尝试主库存、前台、后台；每步验证真实接受结果。
3. 全部失败时记录错误并保留可恢复提示，不静默销毁。
4. 不发放强化器，不设置其他玩法升级，不改变租金、现金或声望。

### 5.3 被动判定

通过 `StartingScenario.ResolveId` 和当前存档的场景 ID 判断制造商，不读取 `StartingPerk`。

- 拾荒优先复用现有 `EventModifier("scav_attempts")` 通道；实现前先定位官方修饰器注册方式，无法使用时才窄补丁 `ScavHelper.GetMaxScavAttempts`。
- 制造成功率在原质量／软顶结果后 +10，强化成功率在原等级结果后 +10，均封顶 100。
- 专精不影响工作量、强化上限、价格或免费强化随机序列。

## 6. 通用组件与材料规划

### 6.1 组件物品

- 1×1，价值 100，最大堆叠 20，合法物品。
- `unitCount` 表示组件数量；视觉只占一格。
- 堆叠要求 ID 与所有权一致，卖家与玩家组件不得合并。
- 不添加违禁、模组或机器标签，不能装入模组舱。

### 6.2 材料计划

输入为当前材料栏的真实 `GameItem` 引用，不把物品先转成仅 ID 的列表而丢失堆叠数量。

计划记录：

```text
MaterialPlan
- recipeVariant
- hasRequired
- consumed[(item, amount)]
- refundLocks[(item)]
- usedShapeArea / entityCount
- failureReason
```

规则：

- 普通物品按实体计数，组件按 `unitCount` 计数。
- 实体数 ≤6、组件 ≤4、电子 ≤2；最终还需按真实形状验证可摆放。
- 只读取制造机材料栏，隐藏栏仅用于已开工材料的暂存与返还。
- 开工前再次验证芯片、配方版本、全部引用、数量和输出槽。
- 先锁定并暂存计划材料，再启动任务；任一步失败都不消耗。
- 完成时按 `(item, amount)` 消耗；组件用拆分或减少 `unitCount`，不得误删整组。
- 取消、失败回流和旧任务返还使用同一数量计划，禁止复制或丢失。
- 不在一次任务中混合主题与通用材料版本。

## 7. 工作量与夜间进度

### 7.1 纯公式

```text
有效速度 = currentSpeed > 0 ? currentSpeed : 33
预计晚数 = max（1，ceil（workload ÷ 有效速度））
```

| 档位 | 工作量 |
| --- | ---: |
| 普通 | 33 |
| 进阶／专用 | 66 |
| 受限神经／精密专用 | 99 |
| 原型专用 | 132 |
| 无限制神经 | 165 |

旧 `BaseNights` 保留为兼容包装，仅返回原基准晚数，不再作为芯片描述中的固定时间。

### 7.2 游戏适配

- 开工时用 `MachineProgressHelper.InitProgressSourceItem` 写入芯片工作量，再启动原生进度。
- 每个有效夜晚由原生机器按当前处理速度推进，已完成的进度不归零。
- 性能模组变化只刷新后续速度和预计晚数，不重写芯片总工作量。
- 输出占用、电力不足或制造取消时不推进。
- 旧 `Legacy` 任务使用已保存的总工作量和当前进度，不重新生成芯片或补算专精成功率。
- tooltip 只显示固定工作量；预计晚数仅由制造预览动态计算。

## 8. 强化等级与事务

### 8.1 上限判定

```text
现有 9 种：MaxLevelFor = 12
新增 19 种：精密强化工艺未解锁 = 8，已解锁 = 12
```

`CanRequestEnhancement` 同时校验：

- 物品属于可强化集合且未安装、未制造、输出未占用。
- 当前等级小于 `MaxLevelFor`。
- 当前存档的精密工艺状态只影响专用模组，不影响现有 9 种。
- 专精和改装能手均不能绕过上限。
- 异常高等级物品不强制降级，但不允许继续强化。

### 8.2 强化事务顺序

1. 只读预览。
2. 点击后重新取得本机材料栏中的同一物品引用并校验上限。
3. 校验金币、触媒、稳固夹和材料栏空间。
4. 准备 B、N、V0 快照。
5. 计算改装能手免费结果，再按原顺序扣费／扣材料。
6. 应用专精修正后的成功率并掷骰。
7. 应用成功、维持、掉级、报废或稳固夹归零。
8. 按新 N 重算三围、专用效果、售价和视觉。
9. 播放结果动画与音效；播放失败只记录，不回滚事务。

## 9. 专用效果规则与适配

### 9.1 纯规则求值

`ModuleCrafterSpecialEffectRules.Evaluate(itemId, level)` 返回纯数据结果：

```text
SpecialEffectState
- outputBonus / yieldBonus / qualityBonus
- workloadReductionPercent / recoveryPercent
- keepTarget / keepDiskMode
- removeContrabandScope
- removePurityPenalty
- extraTraitCount
```

等级映射固定：

- 0～9：基础状态。
- 10～11：第一次提升状态。
- 12：第二次提升状态。
- 掉级、归零、禁用／启用均按当前 N 重算，不累加。
- 19 个物品 ID 均且仅注册一次；未知 ID 返回不支持，不使用默认增益。

实际 +0／+10／+12 数值以功能设计第 10.2 节为唯一源。

### 9.2 原生适配点

| 领域 | 已核实的接入位置或计划检查点 | 适配原则 |
| --- | --- | --- |
| 水培 | `HydroponicHelper.cs`、植物产出与违禁状态处理 | 只修改对应模组的产量／转化／违禁范围，不影响其他植物 |
| 蒸发器 | `MachineEvaporator.cs` 中溶剂模组识别与质量处理 | 保留仅溶剂限制，叠加回收量；现有质量软顶兼容不动 |
| DNA | `MachineDnaManipulator.HasStabilizer`、`GetPrecisionTrait`、`GetExtractionFilter` 及提取结算 | 保留扫描特性与过滤规则，按等级保留目标／数据盘和追加特性 |
| 打印 | `MachinePrinter.CountMeleeBatchModules`、金属／CNC 芯片进度与质量路径 | 只影响对应打印类型，不改变其他芯片 |
| 警报 | `MachineAlarm.Operate` | 保留派系目标和同派系不重复结算，仅替换声望数值 |
| 熔炉 | `MachineFurnace` 的夜间 `onCycleEndSlotItemFunc` | 保持投入数量，按等级调整产出和纯度惩罚 |
| 化学设备 | 原三围计算与安装／提取路径 | 按等级写入质量，保留安装后需提取器拆除 |

水培产量、CNC 工作量和部分 DNA 结算的具体原生方法签名在实现前必须再次核实；不得根据名称猜测补丁目标。所有补丁遇到不支持物品或缺少标签时直接执行原版逻辑。

### 9.3 CNC 工作量

CNC 专用效果先减少对应芯片工作量，再由机器速度计算晚数：

```text
修正工作量 = ceil（原工作量 ×（100－当前修正百分比）÷100）
实际晚数 = max（1，ceil（修正工作量 ÷ 当前处理速度））
```

修正只作用于枪械框架和零件，不影响近战、普通塑料、其他芯片或其他机器。

## 10. 售价与基准状态

### 10.1 新标签

- `MODULE_ENHANCE_BASE_VALUE`：以不变区整数字符串保存 V0，读取为 long。
- `MODULE_ENHANCE_PRICE_ESTIMATED_BOOL`：仅在无法可靠重建旧售价时记录估算状态。
- 现有 `MODULE_ENHANCE_LEVEL_INT` 和三个 B 标签保持不变。

### 10.2 计算顺序

```text
等级售价 = max（1，RoundAwayFromZero（V0 × 新倍率）＋固定词条加减价）
大师售价 = N ≥ 1 且已解锁时，RoundAwayFromZero（等级售价 × 1.10）
```

新倍率表：

```text
100, 110, 120, 135, 150, 170, 195, 225, 260, 305, 365, 440, 560（%）
```

- 固定词条加减价不随等级放大。
- 特殊效果不额外重复计价。
- 始终从 V0 重算，禁止以上一次 `unitValue` 为基准。
- 读档、掉级、归零和禁用／启用使用同一函数。

## 11. 芯片货源与王尔德升级

### 11.1 货源适配

- 合法池：现有 7 种非神经芯片＋新增 16 种合法专用芯片。
- 违禁池：梦魇化、受限神经、无限制神经，违禁等级分别 3、3、4。
- 杰克逊、退休模组商人、普通拾荒和板条箱只允许合法池。
- 小偷、地下渠道、超科技走私贩和王尔德黑市订货只允许对应违禁池。
- 新货骰追加在原货表之后；已生成的按天货表不重掷。
- 受限神经芯片仅从未来的普通退休商人货表移除，不删除当前或已有物品。
- 所有新芯片不读取对应玩法、目标机器或王尔德升级作为出现条件。

### 11.2 升级 ID 与回调

| 计划 ID | 功能 |
| --- | --- |
| `MODULE_CRAFTER_SUPPLY` | 合法电话订货与首次赠送 |
| `MODULE_CRAFTER_WORKSHOP` | 强化器／触媒奖励和合法栏位 |
| `MODULE_CRAFTER_BLACK_MARKET` | 每周违禁订货 |
| `MODULE_CRAFTER_PRECISION` | 专用模组上限提升至 12，开放 +10／+12 效果 |
| `MODULE_CRAFTER_MASTER` | +1 以上最终售价 ×1.10，增加订货栏位 |

旧存档注册定义时保持未购买，不执行 `onUnlock`。只有玩家主动购买后才发放一次即时奖励；重复加载不得重复发放。

## 12. 存档迁移设计

### 12.1 版本与两阶段迁移

使用 `ModHelper.GetModDataInt`／`SetModDataInt` 在当前存档读写 `MODULE_CRAFTER_SAVE_VERSION`，目标版本为 3。

迁移分为：

1. **扫描与计划**：只读检查所有物品、旧任务和网络状态，生成迁移计划与回滚快照。
2. **应用**：按计划修改物品和标签，全部成功后写入版本 3。
3. **失败处理**：应用前异常不修改任何内容；应用中异常按回滚快照恢复，并记录物品 ID 与阶段，不循环重写。

预览不得触发扫描或应用。迁移只在存档加载完成后执行。

### 12.2 应用顺序

1. 注册缺失的网络升级，保持未购买，不执行奖励。
2. 执行现有 2.0.x 遗留强化槽退回逻辑。
3. 将缺少配方版本的旧任务标记为 `Legacy`，保留原工作量、材料、成功率和进度。
4. 为旧存档的原版专用模组建立 B、N=0、V0 快照，保留原生特殊状态。
5. 为现有 9 种已强化物品重建 V0，再应用新倍率。
6. 为旧神经芯片补齐违禁等级，保留所有权、位置和赃物状态。
7. 校验物品数量、任务引用和关键标签后写入版本 3。

商店货表、怜悯计数和随机序列不重掷，新货源从下一次自然刷新出现。

### 12.3 V0 重建优先级

1. 已有新版 V0 标签：直接使用。
2. 已知物品：按 2.1.8 目录价、形状倍率和固定词条重建。
3. 未知来源：N=0 取当前未强化价；N>0 按旧倍率反推并减去固定词条。
4. 仍不可重建：保留当前价作为估算 V0，设置估算标记并只记录一次警告。

禁止在旧当前售价上直接乘新倍率。

### 12.4 降级边界

禁用 3.0.0 可以恢复基础行为，但不承诺直接回滚 2.1.8 无损。旧版无法识别新增芯片、组件、专用强化和网络状态；回滚前必须备份存档。

## 13. UI、文本与刷新

- 专精使用原生专精页。
- 芯片 tooltip 显示工作量、配方档位、违禁等级和主题／通用配方，不显示固定晚数。
- 制造预览显示配方版本、材料、成功率分解和按当前速度预计的晚数。
- 配方切换按钮只在未开工时可用，默认通用；开工后保存并锁定版本。
- 强化预览显示三围、售价、专用效果和失败结果；未解锁工艺时显示 +8 上限。
- +10→+11 明示“专用效果不变”，+9→+10、+11→+12 显示对应提升。
- 所有文本通过现有中英文本地化，其他语言回退英文。
- 刷新沿用现有强化叠加层，不调用会重置拖拽位置的全量布局刷新；保留原位／拖拽显示状态。
- 所有预览只读，不写 B、N、V0，不掷随机数，不推进任务。

## 14. 异常、回退与兼容性

- 不支持的物品、缺少原生对象或存档尚未加载：直接跳过，不修改原版行为。
- 材料不足、空间不足、引用变化或钱不足：整个操作不执行，不部分扣费。
- 迁移失败：按回滚快照恢复并记录阶段，不将存档标记为已迁移。
- 动画、音效或贴图失败：只记录，不影响规则事务。
- 禁用后原生机器回到原版效果；重新启用按 B、N、V0 和网络状态恢复。
- 与其他 mod 的冲突通过保持物品 ID、官方注册入口和窄补丁降低；不承诺未验证的 mod 组合。
